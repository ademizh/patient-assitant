# Помощник пациента: до, во время и после приёма (прототип)

> ⚠️ **Прототип для демонстрации. Не медицинское изделие, не проверен клинически.**
> Программа собирает и упорядочивает сведения, объясняет термины по подключённым источникам и
> оформляет указания врача в список дел. Она **не ставит диагноз, не назначает и не меняет лечение**
> и не заменяет врача.

Приложение на Streamlit, весь интерфейс на русском языке. Одна **запись о приёме** проходит через три этапа:

| Этап | Что делает пациент | Что делает программа |
|---|---|---|
| 🗓️ **До приёма** | Рассказывает о симптомах текстом или голосом, отвечает на уточняющие вопросы по одному, записывает вопросы к врачу | Упорядочивает рассказ с указанием записей-источников (E1, E2…), строит хронологию, показывает изменения симптомов со временем, по желанию подсказывает, к какому врачу обратиться (по источникам), проверяет признаки срочности по **демонстрационным** правилам, формирует отчёт для врача (PDF/JSON) |
| 🩺 **Во время приёма** | Вводит термины, заметки, текст анализов (вставка или PDF с текстом) и вопросы, текстом или голосом | Даёт объяснение из трёх раздельных частей: **что сказано в документе пациента**, **общие сведения из источников**, **что уточнить у врача**. Значения, единицы и референсные интервалы переносятся дословно |
| ✅ **После приёма** | Вставляет, диктует или загружает указания врача | Составляет редактируемый список дел (приёмы, анализы, лекарства, питание, прочее). Слова врача сохраняются дословно, неясности и противоречия отмечаются, напоминания показываются внутри приложения |

Вкладка **📁 Вся запись** показывает всё вместе и даёт скачать запись целиком (PDF/JSON), список дел (PDF) и отчёт для врача (PDF).
Вкладка **📚 База знаний** — вопросы по медицинским документам и управление ими. База хранится отдельно от данных пациента.

## Установка и запуск

Нужен Python 3.10–3.13 (проверено на 3.13).

### Windows (PowerShell)

```powershell
cd путь\к\patient-intake-assistant
py -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
streamlit run app.py
```

### macOS / Linux

```bash
cd patient-intake-assistant
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
streamlit run app.py
```

Откроется `http://localhost:8501`.

* **Демо-режим** (без ключа): в `.env` оставьте `OPENAI_API_KEY=` пустым. Всё работает офлайн на простых правилах, данные не покидают компьютер.
* **Рабочий режим**: впишите ключ в `OPENAI_API_KEY=` и перезапустите приложение. Права ключа: Responses (Write), Audio (Write) и Embeddings (Request).
* Если вы обновляетесь с прошлой версии, удалите из своего `.env` пустую строку `OPENAI_BASE_URL=`, если она там есть.

## Демонстрация от начала до конца (5 минут)

Всё в примере **вымышленное** и так и помечено.

1. **Боковая панель → «👤 Пример».** Создаётся вымышленная запись со всеми этапами, и в базу знаний загружаются демо-документы.
2. **До приёма → «Рассказ о симптомах».** 12 записей пациента, одна из них голосовая (E4, русская речь). Справа видно, какие темы затронуты.
   **«Хронология»:** сроки в формулировке пациента («примерно две недели назад»), упорядоченные приблизительно.
   **«Вопросы к врачу»:** два вопроса взяты из рассказа автоматически.
   **«К какому врачу?»:** терапевт и невролог, с цитатами и страницами демо-источника, и пометка «не диагноз».
   **«Отчёт для врача»:** редактируемый отчёт с противоречием «Аллергии нет» ↔ «аллергия на пенициллин», PDF и JSON.
3. **Во время приёма.** Сохранённые объяснения: X1 «МРТ», X2 «Ферритин» и X3 «мигрень» из заметки пациента.
   В X2 видно, что у ферритина в бланке нет референсного интервала. Программа его не придумывает, а предлагает спросить врача.
   Можно добавить свой термин и нажать «💡 Объяснить».
   Можно загрузить `data/sample_patient/FICTIONAL_lab_results_scan.pdf`: появится понятное сообщение, что это скан.
4. **После приёма.** Список дел из `FICTIONAL_doctor_instructions.txt`. Дозировки сохранены дословно («400 мг», «не чаще 2 раз в сутки»).
   Отмечены: неоднозначность «в ближайшее время», противоречие «Магний B6: 2 раза в день / 1 раз в день» и отсутствие дозировки.
   «Ваша целевая дата» отличается от срока врача. Пункт с прошедшей целевой датой попадает в «Просрочено» и в напоминания.
5. **Вся запись → «⬇️ Вся запись (PDF)».** Документ, где у каждого блока подписано происхождение.
6. Свой сценарий: **«➕ Новая»** создаёт пустую запись. Голосом можно ответить через вкладку «🎙️ Голосом»: запишите речь или загрузите `data/sample_patient/fictional_severity_answer_ru.wav`.

Готовые примеры результатов лежат в `docs/example_appointment/`:
`FICTIONAL_doctor_report.pdf/.json`, `FICTIONAL_appointment_record.pdf/.json`, `FICTIONAL_followup_checklist.pdf`.
Снимки экрана лежат в `docs/screenshots/`.

## Как обеспечивается точность

**Происхождение каждого элемента** хранится в записи и показано цветом и подписью:
«Со слов пациента», «Из документа пациента», «Указание врача», «Объяснение ИИ», «Источник из базы знаний», «Правило (демонстрационное)».

**До приёма**
* Каждое утверждение ссылается на запись пациента. Утверждения без ссылки удаляются, утверждения со слабым совпадением со словами пациента помечаются.
* Отсутствие информации никогда не превращается в «отрицание симптома». Пропущенные темы попадают в раздел «Не хватает информации».
* Сроки сохраняются дословно и в даты не переводятся. Приблизительная оценка нужна только для сортировки.
* Подсказка по специалисту строится только по источникам из базы знаний и показывает их. Варианты без ссылки или с диагностическими формулировками удаляются. Если данных мало, программа задаёт уточняющий вопрос и советует начать с терапевта.
* Срочность проверяется по файлу правил `data/pathways/DEMO_urgent_rules_ru.json`. Это **демонстрационные правила, не проверенные клиницистом**, и это видно в интерфейсе и PDF. Проверенный маршрут подключается через `URGENT_RULES_PATH`, но считается проверенным, только если в нём указаны `validated: true`, `reviewed_by` и `source`.

**Во время приёма**
* Строки анализов разбираются так, что название, значение, единица, интервал и отметка из бланка являются точными подстроками документа.
* Программа не оценивает результат как «норма» или «отклонение» и не дописывает отсутствующий интервал. Предложения ИИ, оценивающие личный результат пациента или похожие на диагноз, удаляются, и об этом сообщается.
* Числа в тексте ИИ, которых нет ни в источниках, ни в документе пациента, помечаются.
* Если в базе знаний нет ответа, программа так и говорит: общий ответ из «памяти модели» не формируется.

**После приёма**
* Каждое действие обязано дословно цитировать слова врача, иначе оно отбрасывается, и об этом сообщается.
* Название, доза с единицей, частота и длительность препарата сохраняются только как дословные фрагменты: без пересчёта, округления и дописывания.
* Срок становится датой, только если врач написал явную дату с годом. Иначе остаётся «не указан». Пациент может задать **свою целевую дату**, которая хранится и показывается отдельно.
* «Просрочено» и напоминания относятся только к пунктам с подтверждённой датой.
* Неоднозначности («по необходимости» без максимума, «в ближайшее время»), отсутствие деталей и противоречия (разные дозы одного препарата, «назначить» и «отменить», разные сроки визита) отмечаются для уточнения у врача.
* При исправлении текста указаний исходный текст сохраняется. При пересборке списка выполненные пункты, ваши даты и заметки переносятся.

**База знаний (RAG)**
* Вопросы на русском. В рабочем режиме запрос дополнительно переводится на английский, поэтому англоязычные источники тоже находятся.
* Ответ всегда на русском. Цитаты из англоязычных источников показываются в оригинале и с переводом, помеченным «Перевод ИИ». Если числа в переводе не совпадают с оригиналом, это отмечается.
* Ссылки проверяются: ссылки на не найденные фрагменты удаляются, а цитаты, которых нет в источнике дословно, отбрасываются. Названия, файлы и страницы берутся из метаданных реальных документов.
* Текст документов и указаний считается **данными, а не инструкциями**: промпты требуют игнорировать встроенные команды, а проверки выше не зависят от модели.

## Данные и их удаление

* Записи о приёме хранятся **локально**: `data/appointments/<id>/record.json`, загруженные файлы лежат в `data/appointments/<id>/uploads/`.
* Они хранятся отдельно от базы знаний (`data/chroma`, `data/library_files`) и никогда в неё не индексируются.
* **«🗑️ Удалить запись»** в боковой панели безвозвратно удаляет запись и все её файлы. Документы базы знаний при этом не затрагиваются.
* В рабочем режиме текст и аудио отправляются в OpenAI. Не указывайте ФИО, адреса и номера документов.
* Приложение не пишет в журнал сведения пациента и ключи. В браузере ошибки показываются только по типу.

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_MODE` | `auto` | `auto` / `demo` / `live` |
| `OPENAI_API_KEY` | — | Ключ OpenAI (без ключа включается демо-режим) |
| `OPENAI_CHAT_MODEL` | `gpt-6-luna` | Модель для обработки, объяснений и списка дел |
| `OPENAI_TRANSCRIPTION_MODEL` | `gpt-transcribe` | Распознавание речи |
| `TRANSCRIPTION_LANGUAGE` | `ru` | Язык речи (пусто — автоопределение) |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` | Эмбеддинги для поиска |
| `APPOINTMENTS_PATH` | `data/appointments` | Где хранятся записи о приёме |
| `URGENT_RULES_PATH` | `data/pathways/DEMO_urgent_rules_ru.json` | Правила срочности |
| `CHROMA_PATH`, `LIBRARY_PATH` | `data/chroma`, `data/library_files` | База знаний |
| `CHUNK_SIZE`, `CHUNK_OVERLAP`, `RETRIEVAL_TOP_K`, `MIN_RELEVANCE` | 900, 150, 4, авто | Параметры поиска |
| `MAX_AUDIO_MB` | 25 | Ограничение размера аудио |

Чтобы сэкономить токены, меняется одна строка: `OPENAI_CHAT_MODEL`. Модель должна поддерживать structured outputs в Responses API.

## Замена демонстрационных документов

Демо-документы в `data/sample_documents/` написаны автором прототипа. Они не являются авторитетным источником и помечены «ДЕМО». Четыре из них на русском (включая заметки о лекарствах из примера) и один на английском (чтобы показать перевод).
Для реального использования удалите их во вкладке «База знаний → Документы» и загрузите проверенные клиническими специалистами материалы в формате PDF с текстом, TXT или Markdown.

## LangGraph: как устроены рабочие процессы

Порядок шагов, ветвления, повторные попытки и паузы управляются **LangGraph**. Модель вызывается через OpenAI SDK
напрямую, поиск идёт через Chroma, а проверки по источникам остаются прежними: LangGraph их не заменяет, а соединяет.

| Граф | Файл | Что делает |
|---|---|---|
| Объяснение | `intake_assistant/graphs/explain_graph.py` | термины, заметки, анализы: подготовка → поиск → генерация → проверка (одна повторная попытка) → итог |
| Опрос до приёма | `intake_assistant/graphs/intake_graph.py` | один вопрос за раз, **пауза** до ответа пациента (`interrupt`), сохранение после каждого шага (SQLite), поправки к прошлым ответам |
| Список дел | `intake_assistant/graphs/checklist_graph.py` | указания врача → пункты с дословной проверкой, отметки неясностей, объяснение лекарств (граф объяснения внутри) |

Пошаговое объяснение для начинающих: **[docs/LANGGRAPH_GUIDE.md](docs/LANGGRAPH_GUIDE.md)**.

Сохранённые шаги опроса лежат в `data/appointments/intake_graph_checkpoints.sqlite` и удаляются вместе с записью.

## API для сайта

```bash
uvicorn api:app --reload
```

Документация откроется на `http://127.0.0.1:8000/docs`. Эндпоинты: `POST /intake/sessions`, `POST /intake/sessions/{id}/reply`,
`GET`/`DELETE /intake/sessions/{id}`, `POST /explain`, `POST /checklist`. В каждом ответе есть `status`, а в `trace` видно,
какие шаги графа выполнились. Это прототип без авторизации — не открывайте его в интернет.

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты работают офлайн: демо-режим, а рабочий режим проверяется с подменённым клиентом OpenAI. Что покрыто:
* отчёт, рассказ и RAG на русском;
* отделение слов пациента от объяснений ИИ;
* дословное сохранение значений анализов и их единиц;
* дословное сохранение указаний о лекарствах;
* отсутствующие даты и противоречия;
* ответы без подтверждения в документах;
* отметка выполнения и её сохранение;
* удаление записи вместе с файлами;
* устойчивость выбора записи;
* распознавание сканов;
* кириллица в PDF;
* графы LangGraph: порядок шагов, одна повторная генерация, пауза и продолжение после перезапуска, поправки, API (`tests/test_graphs.py`).

`python scripts/generate_examples.py` пересоздаёт примеры в `docs/example_appointment/`.
`python scripts/make_sample_assets.py` пересоздаёт демо-PDF и русские аудиофрагменты. Для аудио нужен `espeakng-loader` из `requirements-dev.txt`.

## Ограничения

* **Не проверено вживую с OpenAI** в среде разработки: качество распознавания русской речи, извлечения, объяснений, перевода источников и составления списка дел, а также доступность моделей по умолчанию для вашего аккаунта. Код рабочего режима проверен только с подменённым клиентом. Первый настоящий запуск — это и есть проверка.
* Демо-режим работает на простых правилах и сопоставлении слов, а не на понимании смысла. Он нужен только для показа сценария.
* Русские аудиофрагменты синтезированы движком espeak-ng: голос «роботизированный». Запись с микрофона в браузере в среде разработки не проверялась.
* OCR нет: сканы и фотографии нужно переписать вручную.
* Правила срочности **демонстрационные**. Для реального использования нужен утверждённый клиницистами маршрут.
* Напоминания показываются только внутри приложения, без уведомлений и календаря.
* Несколько встроенных элементов Streamlit остаются на английском, потому что у Streamlit нет настройки языка: подсказка формата даты «dd.mm.yyyy», названия месяцев в календаре и всплывающие подсказки панели таблиц. Подписи загрузчика файлов переведены через CSS.
* Однопользовательский локальный прототип: нет учётных записей и шифрования хранилища.
